# 하이포스 매쓰아일랜드 — 작업 인수인계

학원 학생용 게임 사이트. 전투, 항해, 섬 미니게임, 배 꾸미기가 있습니다.
같은 저장소의 다른 폴더(루트)에 있는 트레저헌터 사이트와는 **별개**이며, 이 폴더(`sea/`)만 작업합니다.

- 이름은 사용자에게 보이는 곳만 바꿨습니다. 주소, Worker, DB 이름은 그대로 `highfos-sea`입니다. 아이콘 원본은 `public/icons/icon.svg`이고, 깃발의 학원 로고는 저장소의 `tools/logo-mark.png`입니다.
- 실서버: https://highfos-sea.highfos.workers.dev
- Cloudflare: Worker `highfos-sea`, D1 `highfos-sea-db`
- 저장소가 **공개**입니다. 설정 코드, DB ID, 학생 정보를 절대 커밋하지 마세요.

## 다른 컴퓨터에서 이어갈 때
`git pull`로 최신 코드를 받고 `sea/` 폴더를 엽니다. 지금 쓰지 않는 이전 작업물은 저장소의 `archive/`에 있습니다.

## 꼭 지킬 것
- 답변은 항상 한국어로. 코드 작업이나 배포 중에도 영어로 바꾸지 않습니다.
- 대상은 고학년입니다. 저학년 기준으로 쉽게 만들지 않습니다.
- 운영자는 AI가 만든 티가 나는 디자인을 싫어합니다. 이모지 장식, 템플릿 아이콘, 영어 제목을 쓰지 않습니다.
- 여학생도 좋아할 요소를 챙기고, 무기는 판타지가 아닌 실제 무기로 합니다.
- 배포는 기존 작업물과 섞이지 않게 분리합니다. 다른 Worker나 DB를 건드리지 않습니다.
- 테스트는 로컬 테스트 계정으로만 합니다. 실서버에 로그인하지 않습니다.

## 구조
- `src/worker.js`: API와 게임 규칙. 서버가 기준입니다. `DECO`(꾸미기), `SHIPS`, `WEAPONS`, `TITLES`, 대결(`duel*`)이 여기 있습니다.
- `public/app.js`: 화면 전체. 템플릿 문자열과 `data-act` 이벤트 방식이며 빌드 단계가 없습니다.
- `public/ship3d.js`: three.js r147(CDN) 3D. `makeShip`이 배와 부착물을 만들고, `fight`가 전투 연출을 합니다.
- `public/voyage.js`, `games.js`, `sound.js`, `style.css`, `sw.js`: 지도·2D 배, 미니게임, 효과음, 스타일, 오프라인 캐시.
- `public/math.js`: 미니게임 수학 문제 생성기. 문제를 저장하지 않고 매번 만듭니다. 고치면 `sea/` 폴더에서 `node tests/math-check.cjs`로 정답을 다시 검사합니다.
- `schema.sql`: 전체 스키마(새 DB용). `migrations/`: 운영 DB에 순서대로 적용한 변경분(001~005 적용 완료).

## 로컬 실행 (`sea/` 폴더에서)
`.dev.vars` 파일을 만들고 `SETUP_CODE=아무-로컬-값`을 적습니다. 이 파일은 커밋되지 않습니다.

```bash
npx wrangler d1 execute highfos-sea-db --local --file schema.sql
```

```bash
npx wrangler dev --port 8791
```

새 로컬 DB는 비어 있습니다. 처음 접속하면 위의 로컬 설정 코드로 교사 계정을 만들고, 반과 학생을 테스트용으로 추가합니다.
로컬 DB에서는 `wrangler.toml`의 `REPLACE_WITH_DATABASE_ID`를 그대로 둡니다. 바꾸면 다른 DB 파일을 보게 됩니다.

## 배포 순서
처음 한 번 `npx wrangler login`을 합니다. 운영 DB ID는 `npx wrangler d1 list`로 확인합니다.

1. 화면 파일을 고쳤으면 `public/sw.js`의 `CACHE` 번호를 올립니다. 지금은 `hs-v32`입니다.
2. DB가 바뀌면 **코드보다 먼저** 운영 DB에 마이그레이션하고 결과를 확인합니다. 과거에 순서를 바꿔 장애가 났습니다.
3. `wrangler.toml`의 `REPLACE_WITH_DATABASE_ID`를 실제 ID로 잠시 바꾸고 배포한 뒤 **반드시 되돌립니다.** ID를 커밋하지 않습니다. ID 조회(`d1 list`)가 실패하면 배포하지 말고 다시 조회합니다. 인증 오류가 가끔 나는데, 빈 ID로 배포될 뻔한 적이 있습니다.
4. 실서버 파일이 새 버전인지 확인하고, 고친 파일만 골라 커밋하고 푸시합니다.

운영 DB 변경과 배포 명령 형식:

```bash
npx wrangler d1 execute highfos-sea-db --remote -y --file migrations/파일이름.sql
```

```bash
npx wrangler deploy
```

## 부착물 분류
- 공용: 랜턴, 가랜드 깃발, 리본 장식, 꽃 장식, 하트 풍선, 요정 전구, 고양이 선원
- 옛날 배 전용(돛단배~갈레온): 닻, 대포, 망루, 앵무새, 보물 더미
- 현대 배 전용: 함재기 5종(순양함부터, 일부는 항공모함부터)
- 옛날 배 전용 목록은 `worker.js`와 `ship3d.js`의 `OLD_ONLY_ATT` 두 곳에 있어 함께 고칩니다.
- 선수상, 테두리, 돛 무늬는 옛날 배 전용으로 둡니다. 운영자가 현대 배에 열지 않기로 정했습니다.

## 수업 요일
- 반마다 `classes.days`에 요일 숫자(0=일요일)로 저장합니다. 기본은 매일입니다. 기존 DB에는 `ALTER TABLE classes ADD COLUMN days TEXT NOT NULL DEFAULT '0123456'`를 실행해 두었습니다.
- 수업 없는 날에는 매일 미션 신청만 막습니다. 매주·도전 미션과 선생님의 승인은 막지 않습니다.

## 실시간 대결
라운드마다 두 학생이 같은 문제를 제한 시간 안에 풉니다. 시간은 1~2라운드 10초, 3~4라운드 15초, 5~8라운드 20초입니다(`worker.js`의 `duelLimit`). 기회는 한 번이고, 맞히면 공격하고 틀리면 공격하지 못합니다. 둘 다 맞히면 먼저 맞힌 쪽이 먼저 쏘고, 피해량에는 전투력을 반영합니다(최대 20% 차이). 최대 8라운드입니다.
- 문제와 채점은 서버(src/duelq.js)가 합니다. 라운드가 끝나기 전에는 정답을 화면에 보내지 않습니다. 고치면 
ode tests/duel-check.mjs로 검사합니다.

## 반 보스 연출
평소 공격마다 장면을 넣지 않습니다. 운영자가 너무 잦다고 정했습니다.
- 손상: 체력 75·50·25%를 넘을 때마다 `snapshot`의 `damage`로 찍은 사진(기울기, 그을림)을 쓰고, 그 위에 `bossFire`의 불과 연기만 움직입니다. 지도 화면에서 3D를 계속 돌리지 않습니다.
- 격파: `bossScene`이 해전 `fight`를 재사용해 학생마다 한 번 보여 줍니다. 승패와 금화는 서버가 이미 정했고 장면은 연출일 뿐입니다.

## 미니게임 수학화
수학반 전용이고 난이도는 초등 고학년 기준입니다. 음수, 문자 방정식, 함수식, 소수(素數)는 쓰지 않습니다. 문제 창을 끼워 넣지 않고 게임 규칙 자체를 수학으로 바꿉니다.
- 완료(전체): 보물 동굴(값이 같은 카드 짝), 암호 등대(수열 규칙 찾기), 통신 기지(식에서 기호 값 찾기), 포격 섬(식을 풀어 안개 속 칸 쏘기, 후반 바람), 포대 요새(빠르기 × 시간으로 쏠 거리 구하기), 사격 훈련장(조건에 맞는 표적), 암초 해협 3곳(정답 통로)
- 점수 범위는 서버의 `GAMES`에 맞춥니다. 제한 시간은 학생 반응을 보고 조정합니다.
- 분수는 항상 세로로 씁니다. 학생들은 `1/5`을 분수로 못 알아봅니다. 화면 글자는 `MathQ.html`, 캔버스 글자는 `games.js`의 `plate`, `rich`를 쓰면 저절로 세로 분수가 됩니다.
- 게임 화면 글자: 제목과 외침은 Jua, 숫자와 문제는 페이지 본문 글꼴(캔버스는 `uiFont()`)을 씁니다. 캔버스에 `sans-serif`를 직접 쓰지 않습니다.
- 틀린 문제는 `games.js`의 `note`로 기록해 결과 카드(`missHTML`)에 보여 줍니다. 서버에 저장하지 않습니다. 새 문제 방식을 넣으면 `note`도 함께 부릅니다.
- 게임 규칙을 바꾸면 `app.js`의 `hs_intro4_` 번호를 올려 설명이 다시 뜨게 합니다.

## 3D 작업 요령
- `new T.Color(c).convertSRGBToLinear()`를 쓰지 않은 재질은 색이 밝게 물 빠져 보입니다. 새 모델은 `solid()`를 씁니다.
- 숨겨진 탭의 3D는 멈춰서 검게 보입니다. 버그로 착각하지 말고 탭을 앞으로 가져온 뒤 확인합니다.
- 전투 1인칭 시야를 가리는 물체는 `fpHide`로 숨깁니다. 새 장식을 달면 전투 시야도 확인합니다.
- 새 모델은 `ship3d.js`의 `solid`, `ball`, `lathe`, `sweep`(굵기가 변하는 관), `many`와 `place`(같은 모양 여러 개), `shingle`(선체에 붙이는 조각) 도우미로 만듭니다.
- 선수상은 앞돛대 지지대(바우스프릿) 아래로 뻗어야 겹치지 않습니다. 크기는 배 길이에 맞춘 `headK`를 따릅니다.
- 휴대폰 크기(390×844) 기준으로 확인합니다.
